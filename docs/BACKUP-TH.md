# คู่มือสำรองและกู้คืนข้อมูล (Backup & Restore) — v1.3.0

ไฟล์สำรองของ Smart Topology เก็บ**ทุกค่าที่ตั้งจากหน้าเว็บ** เมื่อกู้คืนแล้วระบบจะกลับไปเหมือนค่าล่าสุดที่บันทึกไว้ทุกอย่าง
**ไม่ต้องตั้งค่าอะไรเพิ่ม** ทั้งตำแหน่งอุปกรณ์บนแผนผัง คีย์หมอพร้อม รหัสผ่านฐานข้อมูล Custom Query และ API Key

---

## 1. ไฟล์สำรองเก็บอะไรบ้าง

| ส่วน (section) | รายละเอียด |
|---|---|
| `settings` | ชื่อหน่วยงาน รอบการตรวจ timeout เกณฑ์ latency เป้าหมาย SLA |
| `devices` | อุปกรณ์ทั้งหมด: ชื่อ IP วิธีตรวจ/พอร์ต ประเภท ยี่ห้อ/รุ่น VLAN ตำแหน่ง Uplink (parentId) โหมดบำรุงรักษา เปิด/ปิดแจ้งเตือน **พิกัด x/y บนแผนผัง** |
| `users` | ผู้ใช้ทุกคน สิทธิ์ และรหัสผ่าน (เก็บแบบ scrypt hash) |
| `notify` | ช่องทางแจ้งเตือน หมอพร้อม/Webhook/Telegram รวม client-key / secret-key / bot token เงื่อนไขการแจ้ง ตารางส่งรายงาน |
| `mysql` | การเชื่อมต่อ MySQL สำหรับเก็บ log (host user password ระยะเวลาเก็บ) |
| `dbsync` | Master / Slave (host user password database) รอบตรวจ เกณฑ์ delay และ **Custom Query ทุกรายการ** |
| `api` | ตั้งค่า API, CORS และ API Key (hash, สิทธิ์, IP, rate, วันหมดอายุ) — Key เดิมใช้ต่อได้หลังกู้คืน |
| `wazuh` | URL ผู้ใช้ รหัสผ่าน Wazuh API และเงื่อนไขส่ง/รับ Alert |
| `backup` | ตั้งค่าสำรองอัตโนมัติ |
| `seq` | ตัวนับ id ล่าสุด (ป้องกัน id ซ้ำหลังกู้คืน) |
| `alerts` *(เลือกได้)* | ประวัติการแจ้งเตือน · ถ้าไม่เลือก การกู้คืนจะ**คงประวัติปัจจุบัน**ไว้ |

**ไม่อยู่ในไฟล์สำรอง:** log การตรวจใน MySQL (สำรองด้วย `mysqldump` แยกต่างหาก), session ที่ login อยู่ (ทุกคนต้อง login ใหม่หลังกู้คืน)

> ⚠️ ไฟล์สำรองมีรหัสผ่านฐานข้อมูลและคีย์หมอพร้อม จึง**ควรใส่รหัสผ่านเข้ารหัสไฟล์ทุกครั้ง**ที่ดาวน์โหลดออกจากเซิร์ฟเวอร์

## 2. ดาวน์โหลดไฟล์สำรอง (สำรองด้วยมือ)

เมนู **ตั้งค่า → สำรองและกู้คืนข้อมูล → 1. ดาวน์โหลดไฟล์สำรอง** (admin)

1. ใส่ **รหัสผ่านเข้ารหัสไฟล์** อย่างน้อย 8 ตัวอักษร และยืนยันอีกครั้ง
   - ระบบเข้ารหัสด้วย **AES-256-GCM** โดยสร้างกุญแจจากรหัสผ่านด้วย scrypt (N=16384)
   - **ถ้าลืมรหัสผ่านนี้จะเปิดไฟล์ไม่ได้อีก** ให้เก็บในที่ปลอดภัย (เช่นตู้นิรภัย/Password manager ของฝ่าย IT)
2. (เลือกได้) ติ๊ก **รวมประวัติการแจ้งเตือน**
3. กด **ดาวน์โหลดไฟล์สำรอง** → ได้ไฟล์ `smart-topology-backup-YYYYMMDD-HHMM-encrypted.json`
4. เก็บไฟล์ไว้**นอกเครื่องเซิร์ฟเวอร์** เช่น NAS / Google Drive ของหน่วยงาน

ผ่าน API (สำหรับสคริปต์สำรองตามเวลา ต้องใช้ session ของ admin):
```bash
curl -c cj -H "Content-Type: application/json" -d '{"username":"admin","password":"..."}' https://noc/api/login
curl -b cj -H "Content-Type: application/json" -d '{"passphrase":"รหัสไฟล์","includeAlerts":true}' \
     https://noc/api/backup/export | jq .backup > backup-$(date +%F).json
```

## 3. สำรองอัตโนมัติบนเซิร์ฟเวอร์

**3. สำรองอัตโนมัติบนเซิร์ฟเวอร์**
| ช่อง | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| เปิดสำรองอัตโนมัติทุกวัน | เปิด | |
| เวลา | 02:30 | เวลาเครื่องเซิร์ฟเวอร์ (Docker ตั้ง `TZ=Asia/Bangkok`) |
| เก็บไว้ (ไฟล์ล่าสุด) | 14 | ไฟล์อัตโนมัติที่เก่ากว่าจะถูกลบ |
| รวมประวัติการแจ้งเตือน | ปิด | |

- ไฟล์อยู่ที่ `DATA_DIR/backups/` (Docker: ใน volume `/data/backups`) สิทธิ์ไฟล์ `0600` อ่านได้เฉพาะผู้ใช้ที่รันโปรแกรม
- ประเภทไฟล์: **อัตโนมัติ** `auto-…` · **สร้างเอง** `manual-…` (ปุ่ม “สำรองตอนนี้”) · **ก่อนกู้คืน** `pre-restore-…` (สร้างเองทุกครั้งก่อนกู้คืน เก็บ 10 ไฟล์ล่าสุด)
- ไฟล์บนเซิร์ฟเวอร์ไม่เข้ารหัส (ป้องกันด้วยสิทธิ์ไฟล์) · ดาวน์โหลดได้จากปุ่ม ⬇ ในตาราง
- คัดลอกออกนอกเครื่องเป็นประจำ เช่น
  ```bash
  # AlmaLinux + Docker volume
  docker cp smart-topology:/data/backups /backup/smart-topology/
  # หรือ rsync ทุกคืนผ่าน cron
  30 3 * * * rsync -a /var/lib/docker/volumes/nms-data/_data/backups/ nas:/backup/noc/
  ```

## 4. กู้คืนข้อมูล — ทีละขั้นตอน

### 4.1 จากไฟล์ในเครื่องของคุณ
1. **ตั้งค่า → สำรองและกู้คืนข้อมูล → 2. กู้คืนจากไฟล์** → **เลือกไฟล์สำรอง (.json)**
2. ถ้าไฟล์เข้ารหัส ระบบจะขอ **รหัสผ่านไฟล์สำรอง** → กด **ตรวจสอบ**
3. ระบบแสดง**สรุปเนื้อหาในไฟล์** ก่อนกู้คืน: วันที่สร้าง/ผู้สร้าง เวอร์ชัน ชื่อหน่วยงาน จำนวนอุปกรณ์/ผู้ใช้/admin ช่องทางแจ้งเตือน MySQL Master/Slave + จำนวน Query API Key Wazuh
4. ตรวจว่าถูกไฟล์ แล้วกด **กู้คืนจากไฟล์นี้** → ยืนยัน
5. ระบบจะ
   1. ตรวจความถูกต้องทุกส่วน (ต้องมี admin อย่างน้อย 1 คน, ตัด Query ที่ไม่ผ่านการตรวจ SQL, แก้ Uplink ที่ชี้ไปยังอุปกรณ์ที่ไม่มี)
   2. **สำรองค่าปัจจุบันไว้ก่อนอัตโนมัติ** (`pre-restore-…`) — กู้กลับได้ถ้าเลือกไฟล์ผิด
   3. แทนที่ค่าทั้งหมด แล้วเริ่มระบบตรวจสอบ, MySQL log, Master/Slave, Wazuh และตารางส่งรายงานใหม่ด้วยค่าจากไฟล์
   4. ออกจากระบบทุกคน
6. กด **เข้าสู่ระบบใหม่** → ใช้ชื่อผู้ใช้/รหัสผ่าน**ตามที่อยู่ในไฟล์สำรอง**

### 4.2 จากไฟล์บนเซิร์ฟเวอร์
ในตาราง “สำรองอัตโนมัติบนเซิร์ฟเวอร์” กด **กู้คืน** ที่แถวของไฟล์ที่ต้องการ → ยืนยัน (ขั้นตอนเหมือนข้อ 4.1 ข้อ 5–6)

### 4.3 ย้ายเครื่องเซิร์ฟเวอร์ / ติดตั้งใหม่
1. ติดตั้ง Smart Topology บนเครื่องใหม่ (ดู `docs/DEPLOY-TH.md`) แล้ว login ด้วย admin เริ่มต้น
2. กู้คืนจากไฟล์สำรองตามข้อ 4.1
3. ตรวจว่าเครื่องใหม่เข้าถึงอุปกรณ์/MySQL/Wazuh ได้ (Firewall, IP allowlist ของ MySQL user เช่น `'nms'@'IP ใหม่'`)
4. ถ้าใช้ API Key ที่จำกัด IP หรือ Wazuh integration ให้แก้ `hook_url` ใน `ossec.conf` เป็นที่อยู่ใหม่

> รองรับการกู้คืนจากไฟล์ `data/db.json` โดยตรงด้วย (กรณีสำรองโดยคัดลอกไฟล์เดิม)

## 5. ทดสอบว่าไฟล์สำรองใช้ได้จริง (แนะนำทำทุกไตรมาส)
1. รัน Smart Topology ชุดทดสอบอีกตัวบนพอร์ตอื่น
   ```bash
   docker run -d --name st-test -p 3999:3000 -e ADMIN_PASSWORD='Test@123456' ghcr.io/<owner>/smart-topology:latest
   ```
2. เปิด `http://เซิร์ฟเวอร์:3999` → กู้คืนจากไฟล์สำรองล่าสุด
3. ตรวจ: จำนวนอุปกรณ์, แผนผัง Topology ตำแหน่งตรง, ช่องทางหมอพร้อม (อย่ากดส่งทดสอบเพื่อไม่ให้ส่งซ้ำจากสองเครื่อง), Custom Query ครบ
4. ลบชุดทดสอบ `docker rm -f st-test`

## 6. แก้ปัญหา
| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| “รหัสผ่านของไฟล์สำรองไม่ถูกต้อง หรือไฟล์ถูกแก้ไข” | รหัสผิด หรือไฟล์ถูกแก้ไข/เสีย (AES-GCM ตรวจความครบถ้วนของไฟล์) |
| “ไม่ใช่ไฟล์สำรองของ Smart Topology” | เลือกไฟล์ผิด |
| “ไฟล์สำรองมาจากเวอร์ชันใหม่กว่า” | อัปเดตโปรแกรมให้เท่ากับหรือใหม่กว่าเครื่องที่สร้างไฟล์ |
| “ไม่มีผู้ดูแลระบบ (admin) อย่างน้อย 1 คน” | ไฟล์ไม่สมบูรณ์ ระบบปฏิเสธเพื่อไม่ให้ล็อกตัวเองออกจากระบบ |
| หลังกู้คืน login ไม่ได้ | ใช้รหัสผ่านที่อยู่ในไฟล์สำรอง (ไม่ใช่รหัสปัจจุบัน) · ถ้าจำไม่ได้ ให้กู้คืนไฟล์ `pre-restore-…` กลับ (ต้องเข้าถึงเซิร์ฟเวอร์: หยุดโปรแกรม แล้วนำ `data` ของไฟล์นั้นไปแทน `data/db.json`) |
| ข้อความ “ข้าม Query … (คำสั่ง SQL ไม่ผ่านการตรวจ)” | Query ในไฟล์ไม่ใช่คำสั่งอ่านอย่างเดียว ระบบไม่นำเข้าเพื่อความปลอดภัย |
