## 1. หลักการทำงาน

```
 ทุก 10 วินาที (ตามที่ตั้งไว้)
 ┌──────────────┐  ping / TCP   ┌────────────┐
 │ Smart        │ ────────────▶ │ อุปกรณ์ 1..N │
 │ Topology     │ ◀──────────── └────────────┘
 │              │
 │  ① เก็บผลไว้ในหน่วยความจำ (คิว)
 │  ② ทุก 15 วินาที เขียนลง MySQL แบบชุด (batch)
 └──────┬───────┘
        │  ถ้า MySQL ล่ม → เก็บค้างในคิว แล้วเขียนใหม่อัตโนมัติเมื่อกลับมา (ข้อมูลไม่หาย)
        ▼
 ┌────────────────────────────────────────────────────────────────┐
 │ MySQL: smart_topology                                          │
 │  nms_check_log     ← ผลตรวจทุกครั้ง (raw)   เก็บ 30 วัน         │
 │  nms_stats_5min    ← สรุปทุก 5 นาที       เก็บ 90 วัน → กราฟรายวัน │
 │  nms_stats_hourly  ← สรุปรายชั่วโมง        เก็บตลอด → กราฟเดือน/ปี │
 │  nms_event_log     ← เหตุการณ์ ล่ม/กลับมา  เก็บตลอด              │
 │  nms_device        ← ทะเบียนอุปกรณ์ (ซิงก์อัตโนมัติ)                │
 └────────────────────────────────────────────────────────────────┘
```

**ทำไมต้องมีตารางสรุป:** อุปกรณ์ 100 ตัว ตรวจทุก 10 วินาที จะได้ log ดิบ **864,000 แถวต่อวัน** หรือราว 315 ล้านแถวต่อปี
ถ้าดึงกราฟรายปีจากตารางดิบจะช้ามาก ระบบจึงสรุปเป็นราย 5 นาทีและรายชั่วโมงไปพร้อมกัน
กราฟรายปีจึงอ่านจากตารางรายชั่วโมงเพียง ~876,000 แถว และแสดงผลได้ภายใน 1 วินาที

## 2. โครงสร้างฐานข้อมูล

ไฟล์ **`sql/schema.sql`** คือโครงสร้างทั้งหมด (ระบบใช้ไฟล์นี้สร้างตารางเอง และรันด้วยมือก็ได้)

| ตาราง | 1 แถว คือ | คอลัมน์สำคัญ |
|---|---|---|
| `nms_device` | อุปกรณ์ 1 ตัว | `device_id`, `name`, `ip`, `type`, `location`, `is_deleted` (ลบแล้วแต่เก็บไว้ทำรายงาน) |
| `nms_check_log` | การตรวจ 1 ครั้ง | `checked_at`, `status` (online/warning/offline), `success` (1 = ตอบ, 0 = loss), `latency_ms` |
| `nms_stats_5min` | อุปกรณ์ 1 ตัว × 5 นาที | `checks`, `lost_count`, `down_count`, `down_sec`, `sum_latency`, `min_latency`, `max_latency` |
| `nms_stats_hourly` | อุปกรณ์ 1 ตัว × 1 ชั่วโมง | เหมือนข้างบน |
| `nms_event_log` | การเปลี่ยนสถานะ 1 ครั้ง | `event` (down / up / slow / normal / maintenance), `started_at`, `event_at`, `duration_sec` |
| `v_nms_daily` (View) | อุปกรณ์ 1 ตัว × 1 วัน | `loss_pct`, `availability_pct`, `down_sec`, `avg_latency_ms` — พร้อมใช้ใน Excel |

**สูตรที่ใช้ในรายงาน**
- **Packet loss %** = `lost_count ÷ checks × 100` (ครั้งที่ไม่ตอบ ÷ ครั้งที่ตรวจ)
- **Availability %** = `(checks − down_count) ÷ checks × 100` (นับเฉพาะช่วงที่สถานะเป็น offline คือไม่ตอบ 2 รอบติด)
- **Latency เฉลี่ย** = `sum_latency ÷ ok_count`
- **Downtime** = `down_sec` (จำนวนครั้งที่ offline × รอบการตรวจ)
- **จำนวนครั้งที่ล่ม** = จำนวนแถว `event = 'down'`

> อุปกรณ์ที่อยู่ใน **โหมดบำรุงรักษา** หรือ **ปิดการตรวจ** จะไม่ถูกนับ เพื่อไม่ให้สถิติต่ำผิดความจริง

## 3. ติดตั้ง MySQL บนเซิร์ฟเวอร์ (AlmaLinux 8.10)

ข้ามขั้นนี้ได้ถ้าโรงพยาบาลมี MySQL/MariaDB อยู่แล้ว (เช่น เครื่องเดียวกับ HOSxP) แต่**แนะนำให้แยก database ออกจากระบบ HIS**

### ทางเลือก A: MySQL 8.0 (จาก repo ของ AlmaLinux)
```bash
sudo dnf -y module enable mysql:8.0
sudo dnf -y install mysql-server
sudo systemctl enable --now mysqld
sudo mysql_secure_installation        # ตั้งรหัส root, ลบ user ทดสอบ, ปิด remote root
```

### ทางเลือก B: MariaDB 10.11
```bash
sudo dnf -y module enable mariadb:10.11
sudo dnf -y install mariadb-server
sudo systemctl enable --now mariadb
sudo mysql_secure_installation
```

### ตั้งค่าที่แนะนำ
แก้ไฟล์ `/etc/my.cnf.d/smart-topology.cnf`:
```ini
[mysqld]
default-time-zone = '+07:00'            # ให้คำสั่ง NOW() ตรงกับเวลาในรายงาน
character-set-server = utf8mb4          # รองรับภาษาไทย
collation-server = utf8mb4_unicode_ci
innodb_buffer_pool_size = 1G            # ประมาณ 25–50% ของ RAM เครื่อง
# bind-address = 0.0.0.0                # เปิดเฉพาะเมื่อ Smart Topology อยู่คนละเครื่อง
```
```bash
sudo systemctl restart mysqld    # หรือ mariadb
```

### ถ้า Smart Topology อยู่คนละเครื่องกับ MySQL
เปิด firewall **เฉพาะ IP ของเครื่อง Smart Topology** (สมมติ 10.0.10.5):
```bash
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="10.0.10.5/32" port port="3306" protocol="tcp" accept'
sudo firewall-cmd --reload
```

## 4. สร้างผู้ใช้และฐานข้อมูล

เข้า MySQL ด้วย root:
```bash
sudo mysql -u root -p
```
```sql
-- 1) สร้างฐานข้อมูล
CREATE DATABASE smart_topology CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 2) สร้างผู้ใช้เฉพาะระบบนี้
--    'localhost'  = Smart Topology อยู่เครื่องเดียวกัน
--    '10.0.10.5'  = IP ของเครื่อง Smart Topology (กรณีอยู่คนละเครื่อง)
-- กรณีอยู่เครื่องเดียวกัน: สร้างทั้ง localhost และ 127.0.0.1 (บางการตั้งค่า MySQL แยกสองแบบนี้ออกจากกัน)
CREATE USER 'nms'@'localhost' IDENTIFIED BY 'ตั้งรหัสผ่านที่ปลอดภัย';
CREATE USER 'nms'@'127.0.0.1' IDENTIFIED BY 'ตั้งรหัสผ่านที่ปลอดภัย';
GRANT ALL PRIVILEGES ON smart_topology.* TO 'nms'@'localhost';
GRANT ALL PRIVILEGES ON smart_topology.* TO 'nms'@'127.0.0.1';

-- กรณีอยู่คนละเครื่อง: ใช้ IP ของเครื่อง Smart Topology แทน
-- CREATE USER 'nms'@'10.0.10.5' IDENTIFIED BY '...';
-- GRANT ALL PRIVILEGES ON smart_topology.* TO 'nms'@'10.0.10.5';

FLUSH PRIVILEGES;
```

> **หมายเหตุ Docker:** ถ้ารัน container แบบ `--network host` (ตามคู่มือ) ให้ใส่ Host เป็น `127.0.0.1` ใช้ผู้ใช้ด้านบนได้เลย
> ถ้ารันแบบ `-p 3000:3000` container จะมี IP ของตัวเอง (`172.17.x.x`) ต้องสร้างผู้ใช้ `'nms'@'172.17.%'` และใส่ Host เป็น IP จริงของเครื่อง

**สิทธิ์ขั้นต่ำ** (หากไม่ต้องการให้ `ALL`):
`SELECT, INSERT, UPDATE, DELETE, CREATE, CREATE VIEW, INDEX` บน `smart_topology.*`
ถ้าตัด `CREATE` ออก ต้องสร้างตารางด้วยมือก่อน:
```bash
mysql -u root -p < sql/schema.sql
```

## 5. อัปเดตโปรแกรม Smart Topology

เวอร์ชันนี้ใช้ไลบรารี `mysql2` เพิ่ม 1 ตัว

### แบบ Docker (แนะนำ)
```bash
sudo docker pull <ชื่อผู้ใช้>/smart-topology:latest
sudo docker rm -f smart-topology
sudo docker run -d --name smart-topology --restart unless-stopped \
  --network host --cap-add NET_RAW -v nms-data:/data \
  <ชื่อผู้ใช้>/smart-topology:latest
```
ข้อมูลเดิม (อุปกรณ์, ผู้ใช้, การแจ้งเตือน) อยู่ใน volume `nms-data` ไม่หาย

### แบบ docker compose พร้อม MySQL ในตัว
ถ้ายังไม่มี MySQL ใช้ไฟล์ `docker-compose.yml` ที่ให้มาได้เลย:
```bash
# สร้างไฟล์ .env ข้างไฟล์ docker-compose.yml (ห้าม commit ขึ้น Git)
cat > .env <<'EOF'
ADMIN_PASSWORD=รหัสadminครั้งแรก
MYSQL_ROOT_PASSWORD=รหัสrootของMySQL
NMS_MYSQL_PASSWORD=รหัสของผู้ใช้nms
EOF
docker compose --profile mysql up -d
```
MySQL 8.4 จะสร้างฐานข้อมูล `smart_topology`, ผู้ใช้ `nms` และตารางทั้งหมดให้อัตโนมัติ

### แบบรันด้วย Node.js (Windows / ไม่ใช้ Docker)
```powershell
cd smart-topology
npm install          # ติดตั้ง mysql2 (ครั้งเดียว)
node server.js
```

## 6. ตั้งค่าการเชื่อมต่อในหน้าเว็บ

ล็อกอินด้วยบัญชี **admin** → แท็บ **ตั้งค่า** → การ์ด **“ฐานข้อมูล MySQL สำหรับเก็บ Log”**

| ช่อง | ใส่อะไร | ตัวอย่าง |
|---|---|---|
| Host / IP เครื่องฐานข้อมูล | IP หรือชื่อเครื่อง MySQL | `127.0.0.1` หรือ `10.0.10.20` |
| Port | พอร์ต MySQL | `3306` |
| ชื่อฐานข้อมูล | ชื่อที่สร้างในข้อ 4 | `smart_topology` |
| ชื่อผู้ใช้ MySQL | ผู้ใช้ที่สร้างในข้อ 4 | `nms` |
| รหัสผ่าน | รหัสของผู้ใช้ | (แสดงเป็น •••••••• หลังบันทึก) |
| SSL/TLS | ติ๊กเมื่อ MySQL บังคับใช้ SSL | ปกติไม่ต้องติ๊ก |

**ขั้นตอน (ทำตามลำดับ)**
1. กรอกข้อมูลทั้งหมด
2. กด **“ทดสอบการเชื่อมต่อ”** — จะแสดงเวอร์ชัน MySQL และบอกว่ามีฐานข้อมูล/ตารางแล้วหรือยัง
3. ถ้ายังไม่มีตาราง กด **“สร้างฐานข้อมูลและตาราง”** — จะแสดงรายการตารางที่สร้างพร้อมเครื่องหมาย ✓
4. เปิดสวิตช์ **“เปิดการบันทึก log ลง MySQL”**
5. กด **“บันทึก”** → ป้ายมุมขวาบนจะเป็น 🟢 **เชื่อมต่อแล้ว**

ฝั่งขวาของการ์ดจะแสดง **สถานะการบันทึก**: เวลาที่บันทึกล่าสุด, จำนวนแถวที่เขียนแล้ว, จำนวนที่ค้างในคิว และขนาดแต่ละตาราง

> 🔐 รหัสผ่าน MySQL เก็บอยู่ในไฟล์ `data/db.json` ของโปรแกรม (หน้าเว็บไม่เคยส่งรหัสจริงกลับมาแสดง)
> ควรจำกัดสิทธิ์โฟลเดอร์ `data/` และใช้ผู้ใช้ MySQL ที่มีสิทธิ์เฉพาะฐานข้อมูลนี้เท่านั้น

## 7. ตรวจสอบว่าข้อมูลเข้าฐานข้อมูลแล้ว

รอประมาณ 30 วินาทีหลังบันทึก แล้วรันใน MySQL:
```sql
USE smart_topology;

-- log ดิบล่าสุด 10 แถว
SELECT d.name, c.checked_at, c.status, c.success, c.latency_ms
FROM nms_check_log c JOIN nms_device d USING (device_id)
ORDER BY c.id DESC LIMIT 10;

-- สรุปวันนี้รายอุปกรณ์
SELECT * FROM v_nms_daily WHERE log_date = CURDATE() ORDER BY loss_pct DESC;

-- เหตุการณ์ล่ม/กลับมา 20 รายการล่าสุด
SELECT d.name, e.event, e.started_at, e.event_at, e.duration_sec
FROM nms_event_log e JOIN nms_device d USING (device_id)
ORDER BY e.id DESC LIMIT 20;
```

## 8. ใช้งานหน้ารายงาน / สถิติ

แท็บ **รายงาน / สถิติ** (ผู้ใช้ทุกระดับดูได้)

### 8.1 แถบเครื่องมือ
| ส่วน | การใช้งาน |
|---|---|
| **รายวัน / รายเดือน / รายปี** | เลือกระดับของรายงาน |
| **‹ วันที่ ›** | เลือกช่วงเวลา หรือกดลูกศรเพื่อเลื่อนไปช่วงก่อน/ถัดไป · **ปัจจุบัน** = กลับมาวันนี้ |
| **อุปกรณ์ทั้งหมด** | เลือกดูเฉพาะอุปกรณ์ 1 ตัว |
| **ทุกประเภท** | เลือกดูเฉพาะประเภท เช่น เฉพาะ Switch หรือเฉพาะกล้อง CCTV |
| **เปรียบเทียบช่วงก่อนหน้า** | แสดงเส้นประสีเทาของช่วงก่อนหน้า (เมื่อวาน / เดือนก่อน / ปีก่อน) |
| **CSV** | ดาวน์โหลดข้อมูลรายงานเปิดใน Excel |

### 8.2 ความละเอียดของกราฟแต่ละโหมด
| โหมด | 1 แท่ง/จุด = | เทียบกับ | แผนที่ความร้อน |
|---|---|---|---|
| รายวัน | 5 นาที (288 ช่วง) | เมื่อวาน | อุปกรณ์ × ชั่วโมง |
| รายเดือน | 1 วัน | เดือนก่อน | วันที่ × ชั่วโมง + วันในสัปดาห์ × ชั่วโมง |
| รายปี | 1 เดือน | ปีก่อน | เดือน × ชั่วโมง + วันในสัปดาห์ × ชั่วโมง |

### 8.3 อ่านค่าแต่ละส่วน
1. **การ์ดตัวเลข 6 ใบ:** Availability, Packet Loss, จำนวนครั้งที่ล่ม, Downtime รวม, Latency เฉลี่ย, จำนวนการตรวจ
   ป้ายเล็กใต้ตัวเลขคือการเปลี่ยนแปลงเทียบช่วงก่อนหน้า **สีเขียว = ดีขึ้น · สีแดง = แย่ลง**
   (หน่วย “จุด” คือส่วนต่างของเปอร์เซ็นต์ เช่น 0.48% → 0.68% = +0.20 จุด)
2. **สรุปจุดที่ควรสนใจ:** ระบบวิเคราะห์ให้อัตโนมัติ เช่น
   - *ช่วงเวลาที่มีปัญหามากที่สุด* — ชั่วโมงที่ loss สูงสุดของช่วงนั้น
   - *ล่มซ้ำเป็นประจำ* — ชั่วโมงเดียวกันที่ล่มหลายวัน เช่น “02:00–03:00 น. เกิด 31 วันจาก 31 วัน” → มักเกิดจากงานตั้งเวลา (reboot / backup)
   - *ปัญหาเกิดซ้ำทุกวัน…* — วันในสัปดาห์และเวลาเดิมที่ loss สูงกว่าปกติหลายสัปดาห์ เช่น “ทุกวันพุธ 14:00–15:00 น.”
   - *วัน/เดือนที่แย่ที่สุด*, *อุปกรณ์ที่มีปัญหามากที่สุด*, *เหตุการณ์ล่มนานที่สุด*, *เทียบกับช่วงก่อนหน้า*
3. **กราฟ Packet Loss และการล่ม:** แท่งสีชมพู = loss % ของแต่ละช่วง, **แท่งสีแดงเข้ม = ช่วงนั้นมีอุปกรณ์ล่ม**, เส้นประสีเทา = ช่วงก่อนหน้า
   **ชี้เมาส์** ที่แท่งเพื่อดูรายละเอียด (loss, จำนวนครั้งที่ล่ม, downtime และค่าของช่วงก่อนหน้า)
4. **กราฟ Latency เฉลี่ย** และ **Availability:** ดูแนวโน้มความเร็วและความพร้อมใช้งาน
5. **แผนที่ความร้อน (Heatmap):** ช่องยิ่งเข้ม (เหลือง → ส้ม → แดง) ยิ่งมี loss สูง, **ช่องขอบแดง = มีการล่มจริง**, สีเขียวอ่อน = ไม่มี loss
   - แนวตั้งสีเข้มต่อเนื่อง (ชั่วโมงเดียวกันหลายวัน) = ปัญหาตามรอบเวลา
   - แนวนอนสีเข้ม = วันนั้นมีปัญหาทั้งวัน
   - ตาราง **วันในสัปดาห์ × ชั่วโมง** รวมทุกสัปดาห์ ใช้หาปัญหาที่เกิดซ้ำทุกสัปดาห์
6. **อุปกรณ์ที่มีปัญหามากที่สุด:** เรียงตาม loss → downtime กด **“ดูรายอุปกรณ์”** เพื่อเปิดรายงานเฉพาะเครื่องนั้น
7. **ประวัติการล่ม:** ทุกเหตุการณ์ในช่วงนั้น เวลาเริ่ม เวลากลับมา และระยะเวลา (ถ้ายังไม่กลับมาจะขึ้น “ยังล่มอยู่”)

### 8.4 ตัวอย่างการวิเคราะห์
> **โจทย์:** ผู้ใช้แจ้งว่าระบบ HIS ที่ ER ช้าบ่อยในช่วงบ่าย
> 1. เลือก **รายเดือน** → ประเภท **Access Switch** → เปิด **เปรียบเทียบช่วงก่อนหน้า**
> 2. ดู Heatmap “วันในสัปดาห์ × ชั่วโมง” พบช่องแดงที่ **วันพุธ 14:00–16:00**
> 3. ดู “อุปกรณ์ที่มีปัญหามากที่สุด” พบ **Aruba 1930 (ER)** อยู่อันดับต้น → กด **ดูรายอุปกรณ์**
> 4. เลือก **รายวัน** วันพุธล่าสุด ดูกราฟทุก 5 นาที เพื่อระบุเวลาเริ่มและสิ้นสุดที่แน่นอน
> 5. ตรวจสอบงานที่ทำตามรอบเวลา เช่น backup ที่เครื่องในวง ER หรือการ update Windows

## 9. ระยะเวลาเก็บข้อมูลและพื้นที่ดิสก์

วัดจริงประมาณ **110 ไบต์ต่อแถว** (รวม index) · ตั้งค่าได้ในการ์ด MySQL (0 = เก็บตลอด) ระบบลบข้อมูลเก่า **วันละครั้งหลังตี 2** ครั้งละ 20,000 แถว เพื่อไม่ให้ฐานข้อมูลหน่วง

| ตาราง | ค่าเริ่มต้น | ขนาดโดยประมาณ (100 อุปกรณ์ ตรวจทุก 10 วินาที) |
|---|---|---|
| `nms_check_log` (log ดิบ) | 30 วัน | ~864,000 แถว/วัน ≈ 90 MB/วัน → **~2.7 GB** |
| `nms_stats_5min` | 90 วัน | ~28,800 แถว/วัน → **~300 MB** |
| `nms_stats_hourly` + `nms_event_log` | ตลอด | ~876,000 แถว/ปี → **~100 MB/ปี** |

- ถ้าพื้นที่น้อย ให้ลดวันเก็บ log ดิบ หรือ **ปิด “เก็บ log ดิบทุกครั้งที่ตรวจ”** (รายงานทั้งหมดยังทำงานได้ เพราะใช้ตารางสรุป)
- การ์ด MySQL ในหน้าตั้งค่าแสดงขนาดจริงของแต่ละตาราง

## 10. สำรองข้อมูล

```bash
# สำรอง (ไม่ล็อกตาราง ระหว่างนี้ระบบยังเขียนข้อมูลได้)
mysqldump -u root -p --single-transaction --routines smart_topology | gzip > smart_topology-$(date +%F).sql.gz

# สำรองอัตโนมัติทุกคืนตี 3 เก็บไว้ 14 วัน (ใส่รหัสใน ~/.my.cnf ของ root)
echo '0 3 * * * root mysqldump --single-transaction smart_topology | gzip > /opt/nms-backup/mysql-$(date +\%F).sql.gz && find /opt/nms-backup -name "mysql-*.sql.gz" -mtime +14 -delete' | sudo tee /etc/cron.d/nms-mysql-backup

# กู้คืน
gunzip < smart_topology-2026-11-04.sql.gz | mysql -u root -p smart_topology
```

## 11. นำข้อมูลไปใช้ต่อ

**Excel:** ใช้ปุ่ม **CSV** ในหน้ารายงาน หรือเชื่อม Excel → Data → From Database → MySQL แล้วเลือก view `v_nms_daily`

**Power BI / Grafana:** เชื่อมต่อ MySQL ด้วยผู้ใช้แบบอ่านอย่างเดียว:
```sql
CREATE USER 'nms_report'@'%' IDENTIFIED BY '...';
GRANT SELECT ON smart_topology.* TO 'nms_report'@'%';
```

**ตัวอย่าง SQL ที่มีประโยชน์**
```sql
-- อุปกรณ์ที่ล่มบ่อยที่สุด 7 วันล่าสุด
SELECT d.name, COUNT(*) AS times_down, SEC_TO_TIME(SUM(u.duration_sec)) AS total_down
FROM nms_event_log u JOIN nms_device d USING (device_id)
WHERE u.event = 'up' AND u.event_at >= NOW() - INTERVAL 7 DAY
GROUP BY d.name ORDER BY times_down DESC LIMIT 10;

-- loss % แยกตามชั่วโมงของวัน (หาเวลาที่มีปัญหา) 30 วันล่าสุด
SELECT HOUR(bucket) AS hr, ROUND(100 * SUM(lost_count) / SUM(checks), 3) AS loss_pct
FROM nms_stats_hourly WHERE bucket >= NOW() - INTERVAL 30 DAY
GROUP BY hr ORDER BY hr;

-- Availability รายเดือนของอุปกรณ์สำคัญ (ใช้ทำรายงาน SLA)
SELECT DATE_FORMAT(h.bucket, '%Y-%m') AS month, d.name,
       ROUND(100 * (SUM(h.checks) - SUM(h.down_count)) / SUM(h.checks), 3) AS availability_pct
FROM nms_stats_hourly h JOIN nms_device d USING (device_id)
WHERE d.is_critical = 1 GROUP BY month, d.name ORDER BY month, d.name;
```

## 12. แก้ปัญหาที่พบบ่อย

| ข้อความ / อาการ | สาเหตุและวิธีแก้ |
|---|---|
| **ยังไม่ได้ติดตั้ง mysql2** | รันแบบ Node.js แต่ยังไม่ได้สั่ง `npm install` ในโฟลเดอร์โปรแกรม |
| **เชื่อมต่อไม่ได้ (ECONNREFUSED)** | MySQL ไม่ได้เปิด, พอร์ตผิด หรือ MySQL ตั้ง `bind-address = 127.0.0.1` แต่โปรแกรมอยู่คนละเครื่อง |
| **หมดเวลาเชื่อมต่อ** | Firewall ระหว่างสองเครื่องปิดพอร์ต 3306 (ดูข้อ 3) |
| **ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง หรือไม่ได้รับอนุญาตจาก IP นี้** | รหัสผิด หรือสร้างผู้ใช้เป็น `'nms'@'localhost'` แต่ต่อมาจากเครื่องอื่น ให้สร้าง `'nms'@'IP เครื่อง NOC'` เพิ่ม |
| **ไม่มีสิทธิ์ CREATE DATABASE** | ใช้ได้ตามปกติ ถ้ามีฐานข้อมูลอยู่แล้ว ระบบจะสร้างเฉพาะตาราง (หรือรัน `sql/schema.sql` ด้วย root) |
| **ไม่พบฐานข้อมูล / ยังไม่มีตาราง** | กด “สร้างฐานข้อมูลและตาราง” (หรือกดบันทึก ระบบจะลองสร้างตารางให้อัตโนมัติ) |
| **ค้างในคิว (raw) เพิ่มขึ้นเรื่อย ๆ** | MySQL ใช้งานไม่ได้ ระบบเก็บค้างได้สูงสุด 200,000 แถว (ตารางสรุปไม่หาย) และเขียนให้อัตโนมัติเมื่อกลับมา |
| **รายงานขึ้น “ไม่มีข้อมูลในช่วง…”** | ระบบเริ่มเก็บข้อมูลหลังจากเปิดใช้งาน MySQL ข้อมูลก่อนหน้านั้นไม่มี |
| **เวลาใน SQL ด้วย NOW() ไม่ตรงกับในรายงาน** | MySQL ใช้ time zone UTC ให้ตั้ง `default-time-zone = '+07:00'` (ข้อ 3) |
| **ภาษาไทยเป็น ????** | โปรแกรม client ที่ใช้ดูข้อมูลไม่ได้ตั้ง charset เป็น utf8mb4 (ข้อมูลในฐานข้อมูลถูกต้อง) เช่น `mysql --default-character-set=utf8mb4` |
